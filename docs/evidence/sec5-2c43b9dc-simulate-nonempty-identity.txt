Closed class
------------
Before this revision, a synthetic block containing calls exposed no materialized
transaction list, receipt list, transaction/receipt roots, block hash, or usable
successor parent hash. The implementation now retains the exact synthetic
transactions and receipt data produced for each call, derives cumulative gas,
typed receipt roots and logs bloom, constructs the block with fork-appropriate
body fields, exposes hash-only transaction identity, and chains the next
synthetic block to the materialized block hash.

The transaction default follows geth CallDefaults plus
ToTransaction(types.DynamicFeeTxType): a no-gasPrice eth_simulateV1 call in a
synthetic London block uses a type-2 envelope even when the selected base block
is pre-London. Explicit gasPrice remains legacy. Logs emitted by a failed or
reverted top-level call are discarded before call-result and receipt assembly,
matching geth's failed-frame log tracer behavior.

The bounded hash-only implementation rejects returnFullTransactions=true with
JSON-RPC -32602 rather than silently returning hashes. Full synthetic
transaction objects and sender injection remain a separate open class.

RED evidence
------------
1. ETH-RPC-SIMULATE-V1-MATERIALIZES-NON-EMPTY-BLOCK-IDENTITY failed before
   transaction/receipt/block materialization because the non-empty synthetic
   block did not expose the required hash identity.
2. An independent review found that the first implementation used the selected
   base header to choose the default envelope. A temporary mutation removing
   the synthetic dynamic default made the exact transaction-hash assertion fail,
   proving the regression distinguishes type 0 from geth's type 2.
3. Review also found silently accepted returnFullTransactions=true and failed
   call logs entering synthetic receipt identity. Both paths received explicit
   regression assertions before integration.

Review
------
Independent read-only reviews compared the patch to pinned geth. They found and
blocked the initial wrong default envelope, the synthetic-header context issue,
failed-frame log retention, and silent full-transaction acceptance. The final
patch uses the effective synthetic base-fee context, discards failed-call logs,
and rejects the unsupported full-object option. The final focused and cold
verification above was run after those corrections.
