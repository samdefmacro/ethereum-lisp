How the runtime image is handed to Hive

`scripts/hive-run.sh` does not pass an image path to Hive. It installs
`tools/hive/*` as `clients/ethereum-lisp` inside the pinned Hive checkout and
generates a client file naming the runtime image as two build arguments, which
`tools/hive/Dockerfile` consumes as its `FROM ${baseimage}:${tag}`. The client
file generated here at this revision was, verbatim:

  - client: ethereum-lisp
    nametag: ethereum-lisp
    build_args:
      baseimage: ethereum-lisp-runtime
      tag: sec5-3305307d-amd64

`RUNTIME_PREBUILT=1` is what makes the broker use the already-built, already-
exported amd64 image instead of rebuilding from `Dockerfile.runtime`; it
`docker image inspect`s the tag and fails closed if absent. This is the setting
that guarantees the suite runs against the exact reviewed artifact.
