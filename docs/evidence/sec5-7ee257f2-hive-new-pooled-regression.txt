Scope

This revision adds a deterministic integration regression for the
NewPooledTxs case that timed out after LargeTxRequest in the retained Hive
r39 devp2p run. It exercises the eth/72 NewPooledTransactionHashes codec,
production gossip handler, announced-hash queue, request scheduler, and
GetPooledTransactions codec.

The test generates fifty distinct dynamic-fee transaction hashes, announces
their exact type, encoded size, and hash vectors, and requires one outbound
GetPooledTransactions request containing all fifty distinct hashes. It also
requires a positive request ID and proves that the peer queue is drained only
after the request is formed. This matches the pinned upstream case's fifty-item
announcement and complete-set request requirement.

Review

An independent review found that the first draft called
eth-peer-request-announced-transactions directly and therefore could stay green
if the production session pump stopped autonomously selecting and executing its
:drain action. The accepted follow-up runs eth-peer-run-session for one bounded
action instead. The second RED control above proves that this stronger test
fails when pump dispatch no longer invokes the requester. The final test keeps
the pinned eth/72 announcement shape and fifty-item complete request
requirement, plus uniqueness and membership assertions.

Limits

This local RED/GREEN regression protects the announcement-to-request seam. It
is not a successful Hive devp2p rerun and does not prove that the prior timeout
was independent of the preceding LargeTxRequest failure. The independently
rejected r40 request remains rejected because the test host lacks its
fail-closed free-space precondition. This evidence does not prove Hoodi
convergence, eth_syncing=false, shadow comparison, or validator soak
acceptance.
