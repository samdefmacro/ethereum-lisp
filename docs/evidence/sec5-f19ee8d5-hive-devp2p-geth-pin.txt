Independent review found two initial false-evidence paths in HIVE_EXTRA_ARGS.
First, a duplicate GETH_COMMIT followed the protected geth argument, and pinned
Hive stores duplicate simulator build arguments in a last-value-wins map. An
adversarial RED control therefore replaced the final value with forty zeroes
while the result summary would still have printed the reviewed commit. Moving
the protected argument later closed that direct override, but a second review
showed that a following `--` would make Go's standard flag parser ignore every
protected argument appended after it.

The final runner keeps run-identity and source-pin flags before free-form
arguments and rejects one- or two-dash HIVE_EXTRA_ARGS tokens that could replace
client selection/file, simulator, results root, limit semantics, GETH_COMMIT,
branch, or fixtures.
The adversarial GETH_COMMIT plus `--` control now exits 1 before Hive invocation
and names the forbidden token. A second control likewise refuses
`-sim=ethereum/engine`, while benign `--loglevel 4` remains accepted after the
protected pin. This aligns consumed run/source inputs with the reported values.
