Defect and trust boundary

A forkchoice sync target was removed as soon as a noncanonical candidate gained
execution state. During SNAP bootstrap that state transition occurs after the
Consensus Layer's earlier forkchoiceUpdated call returned SYNCING, while the
target is still noncanonical. Consequently `eth_syncing` could become false
before Engine-authorized canonical publication.

The repair keeps the forkchoice target through header/body admission and
candidate execution. `publish-canonical-block` now consumes the exact target
inside the same authorized `chain-store-atomic-commit` that changes the
canonical head and invokes durability. A durability failure journals the target
value and metadata back along with the canonical view. This does not invent a
forkchoice state or canonically publish from P2P/SNAP authority; the CL must
retry forkchoiceUpdated after the target becomes executable.
