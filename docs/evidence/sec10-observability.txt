================================================================================
2. Design
================================================================================

Where: the existing metrics listener. It is already a separate socket, GET
only, unauthenticated by design, loopback unless --metrics.addr says
otherwise. The public RPC port keeps its one POST/JSON-RPC shape and the
Engine port stays JWT-only. Consequence: health probes need --metrics and
--metrics.port, like scrapes. No new CLI option.

Never the store guard. Every input is one of:
  - the sync view the last guard release published, plus the two lock-free
    reads eth_syncing adds (pending forkchoice target count, durable SNAP
    target point read); eth_syncing's own opportunistic guard TRY is not
    used;
  - the store-guard ledger, read racily: two new slots, HOLDER-STARTED-AT
    (written before the label on acquisition, cleared on release) and
    LAST-PRIORITY-AT (stamped when an Engine request asks for the guard,
    before it waits);
  - the peer table's own mutex (never nested in the store guard);
  - the observability sink's own mutex and per-histogram mutexes;
  - rocksdb_property_int, counted as a handle user so a close waits for it.

Readiness checks and thresholds (observability.lisp, defparameters):
  shutdown    no shutdown in progress
  peers       >= 1 connected peer
  sync        eth_syncing false, or head within 2 blocks of the highest
              known target (the Section 10 shadow gate's lag limit)
  storeGuard  current hold <= 8,000 ms (execution-apis engine_newPayload /
              engine_forkchoiceUpdated timeout)
  engine      last Engine request <= 60,000 ms ago (five 12 s slots); null
              before the first
Liveness: shutdown only. A node inside a long SNAP phase or import is busy,
not dead; restarting it discards work. The endpoint's own polling thread
answering is the responsiveness evidence.

Body: {"status":"ok|fail","failed":[names],"checks":[{"name","ok","value",
"limit"}...]}; 200 when ok, 503 otherwise. Integers and fixed names only.

Metrics families (observability sink, layered counting -> observability ->
latency -> node sink). Label vocabularies are fixed (registered Engine
method names via the new ENGINE-RPC-REGISTERED-METHOD-P, fixed activity
labels and thread names, condition class names, refusal verdicts) and each
labelled table folds values past 64 into "other". The store-guard holder
list is exact rather than a prefix because the public RPC names a hold after
the request's own method string. Engine method counting uses the registry
rather than the KZG/BLS-gated availability predicate: the first warm run
counted nothing for engine_forkchoiceUpdatedV3 because the test image had no
KZG backend enabled.
