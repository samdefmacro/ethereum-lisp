Every failure carried the same error. The storage root closure step that
77ab2530 added (sec5-marker-population.txt) walks a chunked contract's whole
local trie once its sixteen cursors complete, then looked up the incomplete
markers of every visited node in ONE native multi-get. The walk admits up to
*SNAP-SYNC-STORAGE-ROOT-CLOSURE-MAX-NODES* (1,048,576) nodes;
+KV-GET-MANY-MAX-KEYS+ is 4,096. The fixtures that verified the step held
2,500-slot contracts, about 2,100 walked nodes each, under the bound; the
live chain's chunked contracts are wider, so every account page that carried
one failed its import and was retried against the next source with the same
result.

The fix, aac5f762

The lookup goes in +KV-GET-MANY-MAX-KEYS+ groups; nothing else in the step
changes. RED control:
SNAP-STORAGE-ROOT-CLOSURE-PUBLISHES-A-TRIE-WIDER-THAN-ONE-MULTI-GET builds a
5,000-slot storage trie with the bare MPT API (a state-db that wide, and the
partition import helper, both exhaust the warm image's heap), stamps the
epoch, marks every node, seeds sixteen completed cursors and publishes.
Against the cceee42f publisher, loaded over the warm image, it fails with
exactly the live error; against aac5f762 it returns :CLOSED with the
:STORAGE-ROOT proof present and every marker gone.
