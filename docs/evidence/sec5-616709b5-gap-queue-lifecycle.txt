Scope

`devnet-node-fill-sync-gaps-with-live-peer` iterates a snapshot of live peer
entries and submits each gap-fill operation to its session-owned request queue.
Normal session teardown closes that queue before removing the entry from the
peer table. A queue can therefore close after the snapshot but before submit.
The prior handler covered only `eth-sync-backfill-peer-error`, allowing the typed
`devnet-peer-request-queue-closed` lifecycle condition to escape and terminate a
continuous-sync coordinator pass before another live peer was tried.

The repair handles only that typed lifecycle condition. It records
`peer.sync.gap_peer_closed`, continues to the next snapshot member, and leaves
ordinary malformed/refused backfill responses on the existing
`peer.sync.gap_peer_failed` path. If no snapshot member succeeds, the existing
multi-peer exhaustion condition still reaches the coordinator retry boundary.
