Section 5: EEST ported_static state tests as an optional, bounded gate

Status

Branch ported-static-gate, from c677bdf0
(c677bdf0507000654916c87e059989ff48950f78, the Amsterdam-inventory merge).  The eight stable
tests@v20.0.2 gates exclude the legacy GeneralStateTests ported into EEST
(state_tests/for_<fork>/ported_static): their discovery list,
+PHASE-A-EEST-STATE-TEST-DISCOVERY-FEATURE-DIRECTORIES+, names no such tree,
and the manifest counts its files as featureTreeNotCovered.  The Amsterdam
refill of those trees had already surfaced one all-fork defect (zero-size
KECCAK256 resized memory, fixed in d7a28c6c) and a 1.9 GB allocation whose
opcode was not traced.

Result: a new optional gate runs every ported_static post entry for Cancun,
Prague and Osaka, 20,701 entries in 62 directories, inside the cold image's
1 GiB heap.  At c677bdf0 it found 61 failing entries and two heap
exhaustions; none is a client divergence.  All 61 were the state-test HARNESS
running a vector differently from the block execute-block would build around
it (three defects, D1-D3), and both exhaustions were the RUNNER (D4, D5).  After
the fixes every entry passes except one per pre-Osaka fork that its own gas
legitimately pays past the harness heap, which is a named skip.  The 1.9 GB
case (stRandom2/random_statetest524) is traced: KECCAK256 of size 0 at offset
CALLVALUE = 0x754eb077, the d7a28c6c shape; it passes at c677bdf0, and a
mutation restoring the pre-d7a28c6c resize makes the new allocation guard fail
it by name instead of allocating.  No consensus code changed; the eight
standard gates' manifest lines are byte-identical to b5161312's.

Not deployed.

================================================================================
1. The gate
================================================================================

  OPTIONAL-EEST-PORTED-STATIC-STATE-TESTS-EXECUTE   (tests/fixture-runner-
    ported-static.lisp, integration) walks state_tests/for_{cancun,prague,
    osaka}/ported_static/<directory>/ one file at a time and runs every post
    entry of the claimed fork through ASSERT-EEST-STATE-TEST-POST-ENTRY, the
    same assertion the stable state gate uses.  It prints one PORTED-STATIC-
    EEST line per fork and directory, the first ten failures, every skipped
    entry by name, and a total per fork, and fails on any failed entry, any
    skip outside the reviewed reasons, or a claimed fork that passed nothing.
  EEST-PORTED-STATIC-STATE-MANIFEST-IS-NON-VACUOUS  counts what the mounted
    corpus offers per fork without executing it, and fails for a fork without
    both valid and invalid entries.
  PORTED-STATIC-EEST-REFUSAL-AND-GATE-VERDICTS-CAN-FAIL (unit) is the
    corpus-free positive control of the classification and both verdicts.

The allocation guard.  go-ethereum prices memory before it allocates it:
core/vm/interpreter.go Run (v1.17.6, lines 200-249) computes memorySize,
charges operation.dynamicGas (memoryGasCost included, core/vm/gas_table.go)
and calls mem.Resize only afterwards, "if memorySize > 0".  An absurd region
is therefore ErrOutOfGas or ErrGasUintOverflow, never an allocation, and one
frame's memory is bounded by the largest W words with 3W + floor(W^2/512) <=
its gas (MEMORY-SIZE-PAYABLE-WITH-GAS; 100,000 gas pays for 6,428 words).  Each
entry runs with *MEMORY-ALLOCATION-CEILING* bound to twice that bound for the
transaction's gas limit (a backing vector never exceeds twice the memory it
holds), capped at 256 MiB, checked where a memory backing vector, a padded
data slice or a memory slice is allocated.  A refusal above what the gas pays
for FAILS the entry as allocationBeyondPaidGas: we allocated what geth would
have refused as out of gas.  A paid allocation refused by the cap is the skip
paidAllocationAboveHarnessCeiling (none occurred).  The condition is a
STORAGE-CONDITION, not an ERROR, so no EVM-ERROR handler can turn it into a
halt and no transaction or block handler into a verdict.

Measured: 62 directories per fork; Cancun and Prague 2,078 files and 7,060
entries (135 invalid), Osaka 1,969 files and 6,581 entries (135 invalid); no
file above the 40 MiB parse bound (the largest is 36.7 MB).

D1.  The harness called APPLY-MESSAGE with no :PREV-RANDAO, whose default is
the zero hash, so opcode 0x44 returned 0 where the environment's currentRandom
belongs.  EXECUTE-BLOCK passes the header's mix hash and post-Merge flag
(src/runtime/execution/block-execution.lisp), so blocks were never affected;
only the fixture harness was.  merge_test (code 3a600055 48600155 44600255)
stores GASPRICE, BASEFEE and PREVRANDAO; the stored 0 instead of
0x15000...00 changed the SSTORE cost and hence the sender's balance
(expected 0x0de0b6b3a20378a2, got 0x0de0b6b3a336285a).  The 17 random tests
read 0x44 the same way (39 wrong-balance and 4 wrong-logs reports in the
baseline log).  Fix eaec700b: pass currentRandom as :PREV-RANDAO and read the
difficulty (:RANDOM-P NIL) only for London, the harness's one pre-Merge fork.
Only this change can alter a successful entry's balance or logs, and after it
all 55 pass.

D2.  low_gas_limit g0 sends 90,000 gas in an 80,000-gas block and expects
GAS_ALLOWANCE_EXCEEDED; the harness executed it.  go-ethereum's state-test
runner applies the message against core.NewGasPool(block.GasLimit())
(tests/state_test_util.go:347), and buyGas's SubGas refuses it with
ErrGasLimitReached; our EXECUTE-BLOCK message list already refuses the same
transaction ("Block gas limit exceeded", src/runtime/execution/
message-lists.lisp).  Fix eaec700b: EEST-STATE-TEST-CHECK-BLOCK-GAS applies
the bound before execution (an Osaka limit above the EIP-7825 cap is left to
the cap check, which geth's preCheck runs first), and GAS_ALLOWANCE_EXCEEDED
maps to that refusal.  RED: the baseline entry "expected TransactionException.
GAS_ALLOWANCE_EXCEEDED, but execution succeeded"; GREEN in the final run.

D3.  create_blobhash_tx is a type-3 transaction with no recipient, expecting
TYPE_3_TX_CONTRACT_CREATION.  We refuse it while decoding its envelope ("Blob
transaction recipient must be exactly 20 bytes"), as go-ethereum's BlobTx,
whose To is a common.Address and not a pointer, cannot decode an empty one
either.  The token mapping accepted only the later execution-time message.
Fix eaec700b: the token also accepts the decode refusal, as
TYPE_4_TX_CONTRACT_CREATION already did.

D4.  FIXTURE-FILE-STRING built the text through a string output stream line
by line; for random_statetest185 (a 16 MB log in one receipt) its buffers and
the final copy at four bytes a character exhausted the 1 GiB heap
(HEAP-EXHAUSTED-ERROR in FIXTURE-FILE-STRING, first run).  Fix 3d8702d9: one
READ-SEQUENCE into one string, and a full collection after any file above
4 MiB.

D5.  static_call1_mb1024_calldepth d1 has 882e9 gas and a contract that
STATICCALLs itself with a 1,000,000-byte argument region until depth or gas
runs out; every megabyte is paid for, so up to 1,024 of them are live at once,
in geth too.  A 1 GiB heap cannot hold that.  Fix 3d8702d9:
*MEMORY-ALLOCATION-HEAP-BUDGET*, bound by the runner to 3/8 of the dynamic
space (3/4 was measured to leave the copying collector no room: the heap was
exhausted inside a collection triggered by a snapshot hash-table grow); an
allocation of 64 KiB or more that would pass it after a full collection is
refused with REASON :HEAP-BUDGET and reported as the named skip
paidMemoryAboveHarnessHeap -- never for more than the gas pays for, which
stays a failure.  At Osaka the same vector's 882e9 gas is above the EIP-7825
cap, so it is refused as a transaction and passes.

Fixture-format or runner gaps, listed apart from divergences: D1-D5 above,
all fixed.  Genuine divergences found: none.
