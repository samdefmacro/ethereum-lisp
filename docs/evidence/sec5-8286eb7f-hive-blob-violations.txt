Implemented behavior

- NewPooledTransactionHashes retains hash, type, and encoded-size metadata.
- Both asynchronous session-pump fetches and synchronous one-shot fetches match
  returned transactions by hash, so legal short and reordered replies remain
  supported.
- A requested response containing an unrequested hash, duplicate hash, wrong
  transaction type, or wrong encoded size signals eth-peer-protocol-error. The
  production peer supervisor converts that condition to a devp2p disconnect.
- Async request metadata is bounded to 64 requests and expires after the pinned
  five-second timeout.
- At the pending-request cap, queued transaction hashes stop being an urgent
  drain action, allowing the session to read replies. Once metadata expires,
  stale entries are pruned and fetching resumes.
