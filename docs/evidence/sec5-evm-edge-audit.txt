1. Memory regions: go-ethereum v1.17.6 against ours
================================================================================

Rules common to every region (go-ethereum):

  G1 core/vm/common.go calcMemSize64 / calcMemSize64WithUint: a size that does
     not fit 64 bits, or an offset that does not, or offset + size wrapping
     2^64, is an overflow (ErrGasUintOverflow); a size of ZERO is memory size 0
     "regardless of offset", even 2^256 - 1.
  G2 core/vm/interpreter.go: memorySize = toWordSize(size) * 32 (overflow ->
     ErrGasUintOverflow); dynamic gas is charged first; memory is resized only
     "if memorySize > 0".
  G3 core/vm/gas_table.go memoryGasCost: a size above 0x1FFFFFFFE0 is
     ErrGasUintOverflow; otherwise words = ceil(size / 32), total = 3 * words
     + floor(words^2 / 512), and the charge is the difference from the last
     total (only when memory grows).
  G4 Every one of those errors is an exceptional halt: evm.Call keeps no gas
     for any error but ErrExecutionReverted.

Ours (src/runtime/evm/memory.lisp): MEMORY-EXPANSION-GAS is 0 for a zero size
and otherwise prices ceil((offset + size) / 32) words with MEMORY-TOTAL-GAS
(3 * words + floor(words^2 / 512)) against the current length, in integers
without a 64-bit bound; ENSURE-MEMORY-REGION, MEMORY-SLICE, COPY-INTO-MEMORY,
COPY-MEMORY-REGION and MEMORY-REGIONS-HIGH-WATER all skip a zero size.  Every
handler charges before it resizes.  Where geth reports an overflow, our price
is at least 3 * 2^59 gas (2^64 bytes); no frame holds that (a transaction is
capped at 2^24 gas under Osaka, EIP-7825), so the charge fails as out of gas:
the same exceptional halt (G4).  Verified by the halt test below: no host
error is reachable on a metered path.

Osaka adds CLZ (no memory); Amsterdam's DUPN, SWAPN and EXCHANGE take no
memory (and Amsterdam execution is gated off).  The dispatcher has no EOF
opcodes.  Precompiles read only the CALL arguments region as their input and
touch no memory of their own; their arithmetic was not in scope (EEST covers
it).

One path diverges and is not consensus: EXECUTE-BYTECODE without :GAS-LIMIT
(gasless diagnostic tooling) charges nothing it can refuse, so a huge nonzero
region there raises a host TYPE-ERROR.  Every consensus and RPC path passes a
gas limit (APPLY-MESSAGE, APPLY-CONTRACT, system calls, call simulation).

2. A condition that escapes block execution
================================================================================

Classification at a6d2b58b.  Block execution ends VALID or in a condition.
BLOCK-VALIDATION-ERROR and TRANSACTION-VALIDATION-ERROR are verdicts (INVALID,
cached in the process); STATE-UNAVAILABLE-ERROR is SYNCING.  Everything else
-- a host TYPE-ERROR (3685491 before d7a28c6c, offset 2^256 - 1), an
arithmetic error, a storage read, a missing BLS/KZG backend -- was re-signalled
unchanged:

  (IMPORT-EXECUTABLE-PAYLOAD,           "Internal error"; the RPC router   engine.execution.internal_error
  ENGINE-NEW-PAYLOAD-MEMORY-STATUS      drops the condition: nothing       (:error) with source engine,

  condition))")

A storage failure while READING state inside execution was a STORAGE-ERROR,
which the coordinator treats as fatal (sec5-sync-outcomes-nonfatal.txt, K6).
It is now BLOCK-EXECUTION-INTERNAL-STORAGE-ERROR: still a STORAGE-ERROR to
every storage-aware caller and test, and contained by the coordinator like the
rest.  Storage failures outside execution (durable exporters, batches) are
untouched and stay fatal.

References.  go-ethereum v1.17.6 is not the model here: eth/catalyst/api.go
newPayload marks the block INVALID (invalidBlocksHits, invalidTipsets) for ANY
error from InsertBlockWithoutSetHead, internal or not.  Nethermind
(references/nethermind, Nethermind.Merge.Plugin/Handlers/NewPayloadHandler.cs,
GetProcessingQueueOnBlockRemoved): ProcessingResult.Exception completes the
wait with an exception, so the request fails with an RPC error and
TryCacheResult never caches it; only ProcessingError is INVALID.  We follow
Nethermind: -32603 for the request, no verdict.

Not verified
================================================================================

- Nothing deployed; no live block has exercised the internal-error path.
- A gap fill or gossiped block that fails internally on a PEER SESSION thread
  still ends that peer's session (peer.dial.failed, as for any session
  error): our defect is charged to the peer that delivered the block.  Not
  tested and not changed.
- The Engine path's prepared-payload shortcut (a newPayload that reuses this
  node's own build) executes through EXECUTE-AND-COMMIT-BLOCK inside the
  classified wrapper, so it is typed, but the devnet executor's log does not
  run for it.
- Staged import gets the typed condition but no log line.
- A persistent internal failure (a corrupt database read, say) is now retried
  on every sync pass with a loud log line each time, instead of stopping the
  node.  No back-off was added.
- The memory audit covers the rules in section 1; precompile arithmetic,
  access-list warmth and EIP-7702 delegation costs were not re-audited.
- cold-all was not run (fleet rule; the coordinator runs it once).
