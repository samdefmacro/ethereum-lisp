Scope

The accepted regression creates a non-empty state root, keeps the canonical
empty trie root as a distinct control, and sends three GetByteCodes requests
through the production eth+snap session pump, request codec, SNAP dispatcher,
persistent backend, response codec, and send path. The requests cover two
distinct state-root-shaped hashes, a repeated unknown state root, and the empty
trie root. Responses preserve request IDs 84, 85, and 86 and contain zero code
items. Unknown state hashes are ordinary misses and are not reinterpreted as
empty code bodies.

RED control

After the valid fixture first passed, the production bytecode backend was
deliberately mutated to manufacture an empty body for an absent hash. The
focused regression failed 0/1 with `snap bytecode record does not match its
content hash`. The mutation was fully reverted; the accepted revision changes
only the test. Two earlier RED attempts exposed fixture errors before the
production boundary (`make-address` received an integer, then the test used an
unavailable `is-false` helper); both were corrected before the meaningful
mutation control and are not counted as mutation evidence.
