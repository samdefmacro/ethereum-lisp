Behavioral contract

GetStorageRanges preserves secure-trie ordering and the pinned geth boundary
rules. An exact origin includes that slot. An exact limit includes that slot.
When the requested limit lies between available slots, the response includes
the next available slot past the limit so the range can be proved.

Regression

tests/eth-pump-tests.lisp adds:
  ETH-PEER-RUN-SESSION-PRESERVES-SNAP-STORAGE-RANGE-BOUNDARIES

The regression creates one account with three storage slots, obtains their
actual secure-trie proof-key order, and drives five requests through the
production eth peer session, SNAP wire codec, request router, and persistent
SNAP backend:

  full zero-to-max range                 -> all three slots
  exact first origin to max             -> all three slots
  origin one past first to max          -> second and third slots
  exact first origin to exact second    -> first and second slots
  origin past first to limit past second -> second and third slots

It checks response message type, request ID, one-account group cardinality,
result cardinality, ordering, and exact returned slot hashes.
