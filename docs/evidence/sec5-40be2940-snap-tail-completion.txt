Scope

This slice closes a false-positive completion boundary in
`devnet-node-snap-sync-pivot-attempt`. After installing the verified SNAP pivot,
the bounded tail importer called `devnet-peer-sync-import-block` with
`require-valid-p`, but that shared forward-acquisition option intentionally
accepts `ACCEPTED` and `SYNCING` as durable buffering outcomes and rejects only
`INVALID`. The caller ignored the returned payload status and could therefore
emit `peer.snap.target_completed` before every post-pivot block was executable.

The fix keeps the forward downloader's established buffering contract unchanged.
At the narrower post-pivot tail boundary, every newly imported block must return
exactly `VALID`; any other payload status raises a storage error before the
completion event. A retry retains the completed pivot/state work, skips tail
blocks whose state is already available, and emits completion only after all
remaining tail imports return `VALID`.
