Defect and implementation

A fetched bare type-3 transaction was decoded successfully and then silently
skipped by `eth-accept-transactions`; it was not classified as a peer protocol
violation. Deterministic sidecar validation failures used
`block-validation-error`, while the production peer supervisor emits the
compressed devp2p Subprotocol-error disconnect only for
`eth-peer-protocol-error`.

The accepted fix now:

- rejects a blob transaction with no network sidecar as
  `eth-peer-protocol-error`;
- translates deterministic malformed/mismatched network sidecar validation
  failures to the same peer-protocol condition;
- deliberately leaves `kzg-unavailable-error` outside that translation, so a
  missing local verification capability is not blamed on the peer;
- retains eth/72's valid omitted-payload wrapper path for GetCells;
- leaves the rejected hash absent from backend pool state, allowing another
  peer to supply the same transaction correctly.

RED and GREEN evidence

The corrected focused regression failed before the production fix with:

  Expected condition ETHEREUM-LISP.VALIDATION:BLOCK-VALIDATION-ERROR was not signaled

The final regression requires `eth-peer-protocol-error` for both missing and
mismatched sidecars, checks that neither poisons pool state, then delivers the
same transaction with a valid sidecar from a fresh peer and observes one pooled
transaction.
