Scope

The accepted regression sends two GetByteCodes requests through the production
eth+snap session pump, request codec, SNAP dispatcher, persistent backend,
response codec, and send path. Each requests three available durable code
bodies, first with a one-byte budget and then with a zero-byte budget. Both
responses preserve their request IDs and return the first exact code body,
proving that the byte target is soft and is checked only after serving an item.

RED control

The production backend was deliberately mutated to reject a code body before
adding it whenever that body would exceed the requested byte target. The
focused regression then failed 0/1 at the exact one-item cardinality assertion.
The mutation was fully reverted; the accepted revision changes only the test.
