Behavioral contract

A snap/1 GetAccountRange request must not serve the currently loaded state when
the requested root is unavailable. Both an arbitrary unknown root and a real
historical root that the configured state provider cannot resolve produce an
AccountRange response with the original request ID, no accounts, and no proof
nodes. A request for the retained current root remains the positive control and
returns its account plus a non-empty proof. The provider-call assertions prove
that unavailable roots pass through the root-indexed resolver while the current
root does not.

Regression

tests/eth-pump-tests.lisp adds:
  ETH-PEER-RUN-SESSION-OMITS-UNAVAILABLE-SNAP-ACCOUNT-ROOTS

The regression drives three requests through the production eth peer session,
SNAP wire codec, request router, and persistent SNAP state backend:

  request 90: arbitrary unknown root -> empty accounts and proof
  request 91: pre-mutation historical root unavailable from provider -> empty
              accounts and proof
  request 92: retained current root -> one account and non-empty proof
