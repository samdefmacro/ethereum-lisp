Three things this shows.

1. The account skip works. 28,665 fetched nodes are the withheld spine, the
   page-boundary paths and the accounts the rebase changed; 2.2 million
   present subtrees were skipped in the first 27 minutes, 3.5 million by
   22:02. On 3305307d the same phase walked the account trie node by node.

2. Every processed node is a marked node. knownIncompleteNodes tracks
   processedNodes one for one and the fetched count is flat, so the walk is
   over ~340,000 PRESENT nodes that carry snap-incomplete-trie-node-v1:
   markers the healer never wrote. The account pages wrote none. The
   partition pages of chunked storage tries did: a partition page proves
   subtrees only at depth four or deeper, so the top of every chunked
   storage trie and most of a mid-sized one stays marked and nothing on the
   range path ever clears it (sec5-marker-population.txt, measured: 4,265
   surviving markers per 2,500-slot contract on a fresh epoch-seven store,
   all on complete content).

3. The local read width fell to exactly one. At 21:21 the width was 22
   (77,860 works over 3,458 batches). From 21:47 on, localReadBatches and
   localReadWorks advance by the same number every window (27,301 in the
   five minutes to 21:57). The read-limiter floor from d5f523a6 is in the
   image and did not apply: the binding term is the checkpoint room,
   max(1, 262144 - (processed - lastCheckpointProcessed)), and a heal
   checkpoint is written only when the frontier is at or below 8,192 works.
   This frontier (127k at the first sample, 651k at 22:02, mostly blocked
   post-order sentinels) never gets there, so after 262,144 processed nodes
   every batch was one work for the rest of the walk
   (sec5-heal-sentinel-width.txt reproduces the cliff at exactly 262,144).

Pivot rebases during healing

At 22:1xZ and again at 22:3xZ a rebase re-seeded the healer from the new
root (counters reset; 414 and 339 fetched). Each generation re-walks the
same marked population, because the markers are deleted only by the walk's
post-order completion, which never arrives before the next rebase. At 215
nodes/s a 340,000-node marked walk takes about 26 minutes, the same order
as the pivot lifetime, and the frontier's blocked sentinels make it longer.
That is the convergence condition this run fails: the marked walk must
finish inside one pivot lifetime.
