2. The five items, against geth v1.17.6
================================================================================

1. An invalid account range or TrieNodes answer from the page's own peer.
   Before: snap-sync-prepare-account-page-range raised the range-proof
   failure (MPT-VERIFY-RANGE-PROOF) and "Snap account response id mismatch"
   as plain ERRORs; the healer's HANDLE-RESULT raised "Snap peer returned an
   unrequested healing node" (and a node that does not decode) as plain
   ERRORs, and snap-sync-heal-request-chunk a TrieNodes id mismatch. Each
   reached DEVNET-NODE-SNAP-IMPORT-WITH-FAILOVER's :ON-SOURCE-ERROR generic
   branch: peer.snap.import_failed, -50, session kept.
   geth: eth/protocols/snap/sync.go OnAccounts ("Account range failed
   proof", returns err) and OnTrieNodes ("Unexpected healing trienodes",
   returns errors.New("unexpected healing trienode")); snap/handler.go
   Handle returns the error and the peer is disconnected. An empty answer
   (statelessPeers) and a node the peer simply lacks are not errors.
   Fix: both verifications run inside SNAP-SYNC-CALL-VERIFYING-RESPONSE
   (kinds "account-range", "trie-nodes"), so they are
   SNAP-SYNC-INVALID-RESPONSE; an empty answer stays
   SNAP-SYNC-STATE-UNAVAILABLE and a local storage fault keeps its type.
   :ON-SOURCE-ERROR ends the session through
   DEVNET-PEER-END-SESSION-FOR-INVALID-DELIVERY (Disconnect 16 on the
   session's own writer, charged -25 at its end), as the pooled dependency
   path already did for StorageRanges and ByteCodes.

2. The multi-peer downloader's :FAILED penalty.
   Before: ETH-SYNC-FETCH-DELIVERY turned every non-malformed failure into
   :FAILED and the main loop charged -25, whatever it was: a stream error, a
   remote Disconnect, a request queue closed under the request.
   geth: eth/downloader/fetchers_concurrent.go -- a request whose send fails
   is unreserved ("the peer was disconnected in between assignment and
   network send"), a peer that leaves has its pending request returned to
   the queue; no score exists at all.
   Fix: ETH-SYNC-DELIVERY-FAILURE-KIND. :LOST for ETH-SYNC-TRANSPORT-LOSS-P
   (STREAM-ERROR, socket error, SB-EXT:TIMEOUT, RLPX-DISCONNECT, the new
   ETH-SYNC-SOURCE-LOST mixin that DEVNET-PEER-REQUEST-QUEUE-CLOSED and
   DEVNET-PEER-REQUEST-ABANDONED now inherit, and an
   ETH-SYNC-PEER-TRANSPORT-ERROR judged by its cause); :INTERNAL for
   ETH-PEER-INTERNAL-ERROR; both uncharged. The source still leaves the
   download (the event marks it, as geth's departed peer). :FAILED -25
   remains for a reply we could not accept; :MALFORMED -50 and :TIMEOUT -10
   are unchanged.

3. The Disconnect a peer sent before our write failed.
   Before: a write that met a closed socket signalled SBCL's "Couldn't write
   ... Broken pipe" and the session ended there; a Disconnect the peer had
   written before closing sat unread.
   geth writes the reason and then closes (p2p/transport.go
   rlpxTransport.close: t.conn.Write(discMsg, ...) under a write deadline,
   then t.conn.Close()), so the reason is on the wire before the close.
   Fix: RLPX-CONNECTION-WRITE-MESSAGE re-signals a stream failure as
   RLPX-WRITE-FAILED (a STREAM-ERROR, so every classification by that type
   holds). CALL-WITH-ETH-PEER-DISCONNECT-DRAIN, around the session pump and
   around the Hello (uncompressed) and Status exchanges, reads on a write
   failure at most four messages the peer already sent, within 0.5 s under
   SB-SYS:WITH-DEADLINE, never writing, and ends the session with the
   RLPX-DISCONNECT it finds (the write failure attached: "peer sent devp2p
   Disconnect (reason 4) before our write failed: ..."). Without one the
   original condition goes on. peer.dial.failed and p2p.peer.session_failed
   now carry "reason" and "disconnectReason"; the session-failure metric
   label is rlpx-disconnect-N for a Disconnect, else the class name.

4. The snap import's per-peer scoring on :ON-SOURCE-ERROR.
   Before: every condition not classified above (unavailable state, an
   exhausted pool, a closed queue, a storage fault) took the generic branch,
   -50: a broken pipe from a failed write, a remote Disconnect, or a defect
   of ours alike.
   Fix: classified the way item 2 classifies: an invalid answer ends the
   session (item 1); a lost transport logs peer.snap.source_lost; anything
   left logs peer.snap.internal_error at error level. None scores. Every
   check of what a peer sent is typed now (account, storage, bytecode and
   trie-node verification), and a message the session could not decode ends
   the session before any worker sees it (queue closed), so what remains at
   the generic branch is ours.

5. Plain ERRORs that escape a peer session and were charged as decoder
   errors. The audit, by file (session-thread paths only):

   Peer's, still charged (-25 at the session's end), unchanged:
     protocol/p2p/connection.lisp  frame/MAC/size, chunking, Snappy and
       message-size errors of RLPX-CONNECTION-READ-MESSAGE
     protocol/p2p/session.lisp  a message id outside every negotiated
       range; an unexpected first message
     networking/eth-sync/peer.lisp  unexpected base-protocol ids; unsolicited
       or unexpected snap responses; "no snap/1 response ... after 256"
     networking/eth-sync/fetch.lisp  "no reply of eth id ... after 256"
     networking/eth-sync/serve.lisp, gossip.lisp  GetBlockAccessLists before
       eth/71, GetCells before eth/72, BlockRangeUpdate before eth/69
     every decode-eth-* / decode-snap-message / RLP decoder
     networking/snap-sync/backend.lisp  a request bound over 32 bytes, an
       empty TrieNodes path set (the peer's request)
   The peer's, now typed ETH-PEER-PROTOCOL-ERROR (so also Disconnect 16):
     serve.lisp  a first receipt index that is negative or beyond the block
   Ours, now typed and uncharged:
     peer.lisp  eth/snap send guards ("not negotiated", "outside the
       negotiated range") -> ETH-PEER-INTERNAL-FAIL
     serve.lisp  building every eth answer (headers, bodies, receipts, BALs,
       cells, the "custody mask" check) -> local work
     gossip.lisp  the accept-transactions predicate, known-transaction
       lookups, batch and blob admission, propagated-block admission,
       serving GetPooledTransactions -> local work; "no blob admission is
       configured" -> ETH-PEER-INTERNAL-FAIL
     pump.lisp  choosing and sending a broadcast, preparing and sending a
       chain update -> local work
     cli/devnet/dialer.lisp  the gap fill's known-block lookups and imports
       -> local work (verdicts, BLOCK-EXECUTION-INTERNAL-ERROR and storage
       faults keep their types)
     snap-sync/backend.lisp  a served storage trie that does not match its
       account, a code record that does not match its hash -> STORAGE-FAIL
       (a local storage fault, already uncharged)
     snap import :ON-SOURCE-ERROR, generic branch -> peer.snap.internal_error
   Fix: CALL-WITH-ETH-PEER-LOCAL-WORK re-signals an error of a class this
   project did not define (ETH-PEER-UNTYPED-ERROR-P: not a transport
   failure, and not named in an ETHEREUM-LISP package) as
   ETH-PEER-INTERNAL-ERROR (OPERATION, CAUSE); anything typed passes through,
   a failed write included. The session still ends (the thread cannot tell
   how far the work got), DEVNET-PEER-SESSION-END-CHARGES-PEER-P does not
   charge it, and DEVNET-PEER-RUN-SESSION logs peer.session.internal_error
   at error level with the operation.

4. Not verified
================================================================================

- Live: nothing deployed. The next Hoodi run should show "before our write
  failed" with a disconnectReason on most of the early broken pipes, the
  session-failure metric split by rlpx-disconnect-N, and no
  peer.snap.import_failed (the event is gone; peer.snap.source_lost,
  peer.snap.internal_error and peer.session.internal_error are counted by
  scripts/hoodi-live-gate.sh logs).
- Whether Linux keeps a peer's last bytes readable after its RST on every
  path is not proven beyond the loopback test (the drain reads what the
  kernel and the stream buffer still hold; nothing else).
- A protocol violation found while the downloader waited on a reply is still
  charged twice: -25 by the downloader (:FAILED) and -25 at the session's
  end. Pre-existing; geth keeps no score and simply disconnects.
- An ETH-PEER-INTERNAL-ERROR from the gap fill's import reaches the sync
  coordinator exactly as the untyped error it replaces did; containing our
  defects there is sec5-sync-outcomes-nonfatal.txt's policy, not changed.
- Snap serving's request callbacks are not wrapped as local work: they mix
  checks of the peer's request with reads of our state, so only the two
  integrity checks of our own state were retyped (as storage faults).
- The snap pool's cooldown and degraded capability after a lost dependency
  transport (DEVNET-SNAP-SOURCE-POOL-FAIL-AND-RELEASE) are unchanged; the
  pool never scored.
- The pivot probe's "Snap account probe response id mismatch" is not typed
  (the probe logs peer.snap.pivot_probe_failed and scores nobody).
- EEST, ported_static, the Hoodi fixtures and replay were not run: no
  execution, gas, state, root or receipt code changed. cold-all was not run
  (fleet rule; the coordinator runs it).
