Scope

The accepted regression drives a GetByteCodes request containing Ethereum's
canonical empty code hash three times through the production eth+snap session
pump, request codec, SNAP dispatcher, persistent backend, response codec, and
send path. Under the pinned 10,000-byte budget, the response must preserve
request ID 85 and contain three zero-length code items in request cardinality.
Duplicate requested hashes are not a set and must not be deduplicated.

RED control

The production bytecode backend was deliberately mutated to remove duplicate
requested hashes before serving them. The focused regression then failed 0/1
at its exact three-item cardinality assertion. The mutation was fully reverted;
the accepted revision changes only the test.
