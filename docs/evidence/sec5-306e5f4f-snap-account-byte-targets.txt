Behavioral contract

Geth appends an account and increases the cumulative response size before
checking whether size is greater than the requested Bytes target. The target is
therefore soft: when accumulated size exactly equals the target, serving
continues, and the next item that crosses the target is included before serving
stops. Geth's pinned devp2p suite exercises this cumulative truncation with
4000-, 3000-, and 2000-byte full-range requests.

Regression

ETH-PEER-RUN-SESSION-STOPS-SNAP-ACCOUNT-RANGE-AFTER-SOFT-LIMIT-CROSSING
creates four committed accounts. A generous baseline response exposes their
actual canonical slim bodies and secure-trie order. The test derives exact
one-item and two-item encoded budgets using geth's 32-byte hash plus encoded-body
account cost. Requests at those exact budgets are then driven through the
production eth-peer-run-session SNAP dispatcher, request/response codecs,
request router, and persistent backend. They must return the first two and first
three accounts respectively, demonstrating both append-before-check and that
serving stops rather than returning all four.
